USER GUIDE

A modern alternative to the 1989 ZIP format

KIS file (.kes) gives you smaller archives, real encryption, and full filename privacy — all from a clean Windows 10/11 app. This guide explains what KIS file is, how to use every feature, and why it is fundamentally safer than ZIP.

1. What is KIS file?

KIS file is a Windows desktop application that creates and opens .kes archives. It was written from scratch in 2026 to fix the structural weaknesses of ZIP, which is now 36 years old. KIS file is a UWP app, signed and packaged as .msix, that runs on Windows 10 (1809+) and Windows 11.

2. Feature overview

📦

LZMA compression

30–50 % smaller than ZIP’s Deflate. Falls back to Deflate automatically when LZMA wouldn’t help.

🔐

AES-256 + HMAC

Encrypt-then-MAC with AES-256-CBC and HMAC-SHA256. Tampering is detected before decryption.

🗝️

PBKDF2 600 000 iterations

Key stretching designed to make brute-force attacks impractical.

🙈

Encrypted filenames

Optional. The entire entry table is sealed — paths, sizes and timestamps are invisible without the password.

✅

Per-file SHA-256

Every file ships with a SHA-256 hash. Corruption is caught immediately.

🔍

Verify without extracting

The new Verify command checks every entry’s HMAC and SHA-256 in place, without writing to disk.

💡

Password hint

Optional reminder stored next to the salt — never the password itself.

🪟

Native Windows UI

Modern Fluent NavigationView with drag-and-drop on the Home and Create pages.

4. Using the application

Create an archive

  1. Open KIS file and click Create.
  2. Drag-and-drop files/folders onto the drop zone, or click Add Files.
  3. Pick a compression algorithm (LZMA is recommended) and a speed.
  4. (Optional) Tick Enable encryption and enter a strong password. You can also tick Encrypt filenames for full metadata privacy.
  5. Click Create archive, choose a destination, done.

Open / extract

  1. Click Open and pick a .kes file (or drop it on the Home page).
  2. If the archive is encrypted you’ll be prompted for the password and shown the optional hint.
  3. Browse the entry list, select what you want, then Extract all or Extract selected.

Verify (new in this build)

Use Verify on the Open page to confirm an archive is intact without extracting it. KIS file will:

  • Recompute the HMAC of every encrypted block.
  • Decompress every entry in memory.
  • Compare each result against the per-file SHA-256 in the entry table.

You get a green OK — N entries verified or a red list of corrupted entries.

Tip: Run Verify after copying an archive over a flaky network or USB stick — it catches damage long before you’d notice on extraction.

5. The .kes file format

+----------------------------+  offset 0
|  Header (56 B, "KESF" …)  |
+----------------------------+
|  Encryption block          |  only if encrypted
|    salt (32 B) + hint      |
+----------------------------+
|  Per-file data blocks      |  IV(16) | HMAC(32) | LZMA/Deflate(ciphertext)
|  …                         |
+----------------------------+
|  Entry table               |  paths, sizes, offsets, SHA-256, type
|  (sealed when              |  ↳ wrapped in AES+HMAC if EncryptFileNames=on
|   EncryptFileNames=on)     |
+----------------------------+

Why “Encrypted filenames” matters

In a password-protected ZIP, anyone can still see tax-return-2025.pdf, passwords.kdbx, or your folder layout. With KIS file’s encrypted-filename mode the entire entry table is sealed with AES-256+HMAC, so the archive becomes an opaque blob: only the magic KESF, version, and total sizes are visible.

6. Recommended workflow

  • Use LZMA + speed Normal for everyday archives.
  • Switch to Maximum only for cold storage; it uses a 32 MB dictionary and is markedly slower.
  • For sensitive data, always enable encryption and tick Encrypt filenames.
  • Use Verify after copying or downloading.
  • Pick passwords ≥ 12 chars; PBKDF2’s 600 000 iterations are strong but cannot rescue a 4-digit PIN.

8. Installation

  1. Unzip KISfile-Setup.zip.
  2. Right-click Install.bat → Run as administrator (only needed once to trust the developer certificate).
  3. Launch KIS file from the Start menu.

9. Limitations & roadmap

  • In-memory I/O. The current build reads each file fully into memory before compressing — fine for documents, but very large media files (multi-GB) should be split first.
  • Split archives. The header reserves fields for multi-part archives; the writer for that mode is not yet wired to the UI.
  • Streaming extraction. Planned: per-block streaming for files larger than 2 GB.
